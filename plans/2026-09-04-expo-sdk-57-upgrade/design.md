# Design — Апгрейд Expo SDK 54 → 57

Дата: 04.09.2026

## Целевое состояние

- `package.json` и `app.json` описывают проект на Expo SDK 57: React Native 0.86, React 19.2, все Expo-пакеты в версиях, которые резолвит `expo install --fix` для SDK 57.
- Приложение запускается в Expo Go SDK 57 на iPhone без ошибки несовместимости и в Expo Go на Android.
- `rtk yarn lint` и `rtk yarn tsc --noEmit` проходят без ошибок.
- CI публикует OTA-апдейт на Node 22 и вызывает `eas update` с обязательным флагом `--environment`.
- `expo.runtimeVersion` в `app.json` поднят: изменение нативное, старые установленные сборки к новым апдейтам не допускаются.
- Правила проекта (`CLAUDE.md`, `ai/rules/**`) называют актуальные версии SDK, RN, React и остальных закреплённых пакетов.

## Стратегия

Инкрементальный подъём по одной мажорной версии: 55, затем 56, затем 57. Каждая ступень — отдельная фаза с одинаковым набором шагов: установка, `expo install --fix`, `expo-doctor`, lint + tsc, дымовой прогон в Expo Go на Android. Ступень считается закрытой только после успешного прогона; ошибки чинятся внутри своей ступени, а не переносятся дальше.

Обоснование: между 54 и 57 три мажора RN и один мажор React. Единовременный прыжок смешивает причины поломок — edge-to-edge, отвязку expo-router от React Navigation и смену версии Hermes нельзя будет развести по источникам.

## Ключевые решения

| Решение | Выбор | Причина |
|---------|-------|---------|
| Способ вернуть работу на iPhone | Апгрейд SDK | Development / preview build требует платного Apple Developer Program |
| Порядок версий | 55 → 56 → 57 по одной | Локализация поломок; рекомендация Expo |
| NativeWind | Остаётся v4, пока работает | v5 тянет за собой Tailwind 4.1 и смену всех конфигов; включается только по триггеру |
| Reanimated babel-плагин | `react-native-worklets/plugin` | Старый путь молча перестаёт трансформировать ворклеты |
| Платформа проверки во время апгрейда | Android + Expo Go | На Android ставится Expo Go любой версии APK-файлом, iPhone проверяется в конце |
| `react-native-linear-gradient` | Удаляется | Не импортируется; в проекте используется `expo-linear-gradient` |
| Нативные проекты | CNG, каталоги `android/` и `ios/` не создаются | Сборка в облаке EAS, локальный Mac не нужен |

## Триггер условной фазы NativeWind

Переход на v5 выполняется только если после установки SDK 57 наступает хотя бы одно:
- сборка Metro падает на `nativewind/metro` или `nativewind/babel`;
- классы не применяются к элементам в рантайме;
- `expo-doctor` или Metro сообщают о несовместимости NativeWind с установленной версией React Native.

Иначе фаза закрывается как `deferred` с записью проверки в evidence.

## Риски

| Риск | Влияние | Реакция |
|------|---------|---------|
| NativeWind v4 несовместим с RN 0.86 | Ломается вся вёрстка | Условная фаза миграции на v5; стоимость низкая — кастомной темы нет |
| Edge-to-edge на Android | Контент под системными барами | Отдельная фаза ревизии отступов через safe-area |
| Сторонние библиотеки без поддержки RN 0.86 | Падение экранов графиков, иконок, date-picker | Проверка на каждой ступени, апгрейд мажоров вручную |
| Память Hermes V1 с reanimated | Рост потребления на SDK 56 | Ступень 56 — промежуточная, состояние фиксируется, чинится переходом на 57 |
| Бамп `runtimeVersion` | Установленные сборки перестают получать OTA | Явная запись в фазе релиза; проверить наличие нативных билдов заранее |
| Дрейф CI | Публикация падает на Node 20 или на отсутствии `--environment` | Отдельная фаза правки workflow до первого пуша в `main` |

## Границы

- Апгрейд NativeWind до v5 без срабатывания триггера.
- Переход на development / preview build и работа с Apple Developer Program.
- Изменение бизнес-логики, экранов и API-контрактов.
- Добавление тест-раннера.
- Регенерация Orval (контракт бэкенда не меняется).
