# Phase 11 — Версия и CHANGELOG

Status: done
Model tier: FAST
Required rules: `ai/rules/common/versioning-changelog.md`

## Goal

Версия согласована между `package.json`, `app.json` и веткой, задача записана в CHANGELOG, `runtimeVersion` отражает нативный характер изменения.

## Implementation notes

Целевая версия задаётся пользователем и до этого момента не подставляется. Фаза не выполняет git-операций.

По результату Phase 01 нативных билдов не существует — подъём `runtimeVersion` безопасен и не отрезает никого от OTA.

## Scope

- `package.json` — поле `version`
- `app.json` — `expo.version` и `expo.runtimeVersion`
- `CHANGELOG.md` — секция целевой версии

## Checklist

- [x] Получить целевую версию от пользователя
- [x] Привести `version` в `package.json` и `expo.version` в `app.json` к целевой версии
- [x] Поднять `expo.runtimeVersion` — смена React Native и React требует нового нативного билда; установленных сборок нет, риска отсечения от OTA нет
- [x] Добавить запись в CHANGELOG: секция целевой версии с датой в формате `DD.MM.YYYY`, новый пункт первым в списке
- [x] Пункт не длиннее пяти слов и называет задачу, а не её состав
- [x] Сверить название текущей ветки с `r-<версия>` и сообщить о расхождении, не переключаясь

## Verification commands

- `rtk grep -n "\"version\"" package.json app.json`
- `rtk head -10 CHANGELOG.md`

## Acceptance criteria

- Версии в двух файлах совпадают с целевой
- `runtimeVersion` отличается от прежнего значения `1.0.0`
- Секция CHANGELOG стоит первой в файле и датирована днём внесения записи

## Evidence note

Выполнено:
- `expo.runtimeVersion` в `app.json` поднят с `1.0.0` до `2.0.0`. Смена React Native 0.81 → 0.86 и React 19.1 → 19.2 требует нового нативного билда, значит прежний токен совместимости обязан смениться. Побочного ущерба нет: по данным Phase 01 нативных сборок проекта не существует, отсекать от OTA некого. Expo Go при этом руководствуется `sdkVersion`, а не `runtimeVersion`
- Текущая ветка — `r-1.8.0`, `version` в `package.json` и `expo.version` в `app.json` равны `1.8.0`, в `CHANGELOG.md` есть секция `[1.8.0] 17.08.2026`

Целевая версия задана пользователем: `1.9.0`.

- `version` в `package.json` и `expo.version` в `app.json` подняты с `1.8.0` до `1.9.0`
- В `CHANGELOG.md` добавлена секция `[1.9.0] 04.09.2026` первой в файле, с единственным пунктом `- Апгрейд Expo SDK 57` — четыре слова, укладывается в лимит, называет задачу без перечисления состава

Расхождение по ветке: текущая ветка `r-1.8.0`, правилу соответствует `r-1.9.0`. Сообщаю о расхождении и не переключаюсь — git-операции выполняет пользователь. Предлагаемая команда: `rtk git checkout -b r-1.9.0`.

- Ветка не соответствует версии: `r-1.8.0` против ожидаемой `r-1.9.0` — переключение за пользователем
