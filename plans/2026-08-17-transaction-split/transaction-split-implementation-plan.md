# Разделение платежа — Implementation Plan

Дата: 17.08.2026
Целевая версия: 1.8.0

## Goal

- Расходную транзакцию можно разделить: часть суммы уходит в новый платёж с собственной категорией, остаток остаётся в исходной транзакции.
- Сохранение отправляет два запроса: обновление исходной транзакции и создание новой, где всё кроме категории и суммы копируется из исходной.

## Task profile

Profile: `feature` (4 сигнала)

| Сигнал | Наличие |
|--------|---------|
| Новый UI-блок и новое состояние экрана | да |
| Изменение контракта сохранения (два запроса вместо одного) | да |
| Кросс-слойные изменения: `features` + `shared/constants` | да |
| Архитектурный компромисс: нетранзакционное сохранение | да |
| Детерминированный баг с минимальной правкой | нет |

## Decisions taken

- Разделение доступно только для типа `expense` и только в режиме редактирования существующей транзакции.
- Ровно одна дополнительная часть за раз; повторное разделение недоступно, пока часть не удалена.
- Верхнее поле «Сумма» на время разделения read-only и показывает остаток: базовая сумма минус сумма новой части.
- Базовая сумма фиксируется в момент включения разделения, включая ручные правки пользователя.
- Порядок запросов: сначала обновление исходной транзакции, затем создание новой.
- Целевая версия — 1.8.0, запись добавляется в существующую секцию CHANGELOG с датой 17.08.2026.

## Assumptions

- Бэкенд не предоставляет атомарной операции разделения — транзакционность обеспечивается только порядком запросов и обработкой частичного успеха на клиенте.
- Generated-DTO `CreateWalletTransactionDto` и `UpdateWalletTransactionDto` остаются нетипизированными; регенерация Orval в рамках этой задачи не требуется.
- Изменение JS-only, OTA-совместимо, `runtimeVersion` не меняется.
