# Design — Разделение платежа

Целевое состояние экрана редактирования транзакции.

## Поведение

Разделение доступно, когда одновременно выполнены условия: тип транзакции `expense` и экран открыт в режиме редактирования существующей транзакции.

Под карточкой формы находится второстепенная кнопка «Разделить платёж». Нажатие открывает карточку разделения и скрывает кнопку.

Карточка разделения содержит ровно один новый платёж:
- строка «Категория» (обязательна)
- строка «Подкатегория» (только если у выбранной категории есть подкатегории)
- поле суммы нового платежа
- кнопка удаления, возвращающая экран в обычное состояние

При включении разделения фиксируется базовая сумма — актуальное значение поля «Сумма» на этот момент, включая ручные правки пользователя. Поле «Сумма» становится нередактируемым и показывает остаток: базовая сумма минус сумма нового платежа. Под полем — подпись «Остаток после разделения».

Ввод суммы нового платежа ограничен диапазоном от нуля до базовой суммы. Удаление разделения возвращает полю «Сумма» базовое значение и редактируемость.

Смена типа на `income` или `transfer` полностью сбрасывает разделение.

## Сохранение

Кнопка «Сохранить» при активном разделении выполняет два запроса последовательно:

1. `PATCH wallets/transactions/{id}` — исходная транзакция с уменьшенной суммой (остаток) и остальными полями формы без изменений.
2. `POST` создание новой транзакции через generated-хук: `walletId`, `type`, `description`, `transactionTime` копируются из формы исходной транзакции; `categoryId`, `subCategoryId`, `amount` берутся из карточки разделения; `targetWalletId` и `targetAmount` не передаются.

Обе суммы отправляются в копейках со знаком расхода (отрицательные).

Экран закрывается и кэш инвалидируется только после успеха обоих запросов. Инвалидируются `QUERY_KEYS.transactions.all` и `QUERY_KEYS.wallets.all`.

## Частичный успех

Между двумя запросами возможен разрыв: первый прошёл, второй упал. Целевое поведение:

- Экран остаётся открытым, показывается сообщение о том, что сумма исходной транзакции уже уменьшена, а новый платёж не создан.
- Фиксируется признак того, что исходная транзакция уже обновлена.
- Повторное нажатие «Сохранить» при этом признаке выполняет только создание новой транзакции — повторного вычитания суммы не происходит.
- Признак сбрасывается при успешном завершении обоих шагов, при отключении разделения и при смене типа транзакции.

## Валидация

| Условие | Сообщение |
|---------|-----------|
| Сумма нового платежа не число или ≤ 0 | Введите сумму нового платежа |
| Сумма нового платежа ≥ базовой суммы | Сумма разделения не может превышать сумму транзакции |
| Категория нового платежа не выбрана | Выберите категорию нового платежа |

Валидация выполняется до первого запроса — при ошибке ни один запрос не уходит.

## Структура файлов

| Файл | Назначение |
|------|-----------|
| `src/features/operations/EditTransactionScreen/useTransactionSplit.ts` | Состояние разделения, базовая сумма, остаток, клампинг ввода, сброс |
| `src/features/operations/EditTransactionScreen/SplitPaymentCard/SplitPaymentCard.tsx` | Карточка нового платежа: категория, подкатегория, сумма, удаление |
| `src/features/operations/EditTransactionScreen/SplitPaymentCard/SplitButton.tsx` | Кнопка «Разделить платёж» |
| `src/features/operations/EditTransactionScreen/useEditTransactionScreen.ts` | Подключение хука разделения, валидация, вызов сохранения |
| `src/features/operations/EditTransactionScreen/useEditTransactionActions.ts` | Последовательность PATCH → POST, признак частичного успеха |
| `src/features/operations/EditTransactionScreen/EditTransactionScreen.tsx` | Рендер кнопки, карточки разделения, read-only режима поля суммы |
| `src/shared/constants/transactionSplit.ts` | Константы разделения (тексты валидации не хардкодятся в двух местах) |

Ограничения слоёв: новые файлы живут в `features`, `expo-router` в них не импортируется, суммы в копейках конвертируются существующими утилитами из `shared/utils/currency`.

## Стилизация

NativeWind `className`, палитра существующего экрана: фон карточки `#10101C`, границы `white/[0.08]`, акцент расхода `#FF4B6B`, вторичный текст `#8888AA`, приглушённый `#44445A`. Кнопка «Разделить платёж» — outline, без заливки. Read-only поле «Сумма» визуально приглушается. Инлайн `style` допускается только для динамического цвета акцента, как в существующем коде.
