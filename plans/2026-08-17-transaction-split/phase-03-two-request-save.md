# Phase 03 — Сохранение двумя запросами

Status: done
Model tier: DEEP
Required rules: `ai/rules/projects/fin-app-mobile/state-management.md`, `ai/rules/common/patterns.md`

## Goal

Сохранение при активном разделении обновляет исходную транзакцию и создаёт новую, корректно переживая отказ второго запроса.

## Implementation notes

`useEditTransactionActions.ts` патчится: обе мутации уже есть, добавляется последовательный сценарий и признак частичного успеха. Валидация разделения добавляется в `onSave` внутри `useEditTransactionScreen.ts` рядом с существующими проверками.

## Scope

- `src/features/operations/EditTransactionScreen/useEditTransactionActions.ts` — последовательность PATCH → POST, признак частичного успеха, сообщения об ошибках
- `src/features/operations/EditTransactionScreen/useEditTransactionScreen.ts` — валидация разделения, сбор payload новой транзакции
- `src/shared/constants/transactionSplit.ts` — тексты валидации и сообщения частичного успеха

## Acceptance criteria

- Двойное нажатие «Сохранить» не отправляет дублирующие запросы
- Ни один сценарий не приводит к повторному вычитанию суммы из исходной транзакции
- Обычное сохранение без разделения ведёт себя ровно как раньше — один запрос
- Логика перевода (`targetAmount`, кросс-курс) не затронута

## Evidence note

Изменено:
- `useEditTransactionActions.ts` — мутации переведены на `mutateAsync`, `handleSave(payload, splitPayload?)` выполняет PATCH → POST последовательно; общий билдер `toCreateData`; состояние `isSourceUpdated` и метод `resetSplitProgress`
- `useEditTransactionScreen.ts` — `validateSplit`, сумма исходной транзакции берётся из `split.remainderAmount`, `splitPayload` собирается спредом основного payload с переопределением кошелька, суммы и категорий; обёртка `resetSplit` дополнительно сбрасывает признак частичного успеха
- `useTransactionSplit.ts` — добавлены `remainderAmount` и `splitAmount` в единицах валюты
- `EditTransactionScreen.tsx` — кнопка удаления разделения вызывает `onRemoveSplit`

Ключевая деталь реализации: признак частичного успеха дублируется локальной переменной внутри `handleSave`, потому что состояние React не обновляется в пределах одного вызова — без этого сообщение об ошибке второго запроса было бы неверным.

Единицы суммы: отправляются в единицах валюты, а не в копейках — так работает существующий контракт (`parseAmountInput` без умножения). Разделение следует ему же, конвертируя свои копейки обратно.

Гейты: `yarn lint` — 0 ошибок (2 прежних предупреждения в `useDashboardScreen.ts`); `yarn tsc --noEmit` — чисто.

Отклонение: `useEditTransactionScreen` вырос до 138 строк при лимите 50, `useEditTransactionActions` — до 79. Часть долга унаследована, часть добавлена этой фазой. Разбор в фазе 04.
