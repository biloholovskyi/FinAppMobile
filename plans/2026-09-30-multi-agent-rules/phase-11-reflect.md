## Уроки

- `@` перед путём в таблице `CLAUDE.md` — это импорт: таблица «Load Rules By Task» грузила 19 правил (104 KB) в каждую сессию. Теперь `@` — только у 6 намеренных импортов, итог проверен новой сессией
- Claude кэширует тела скиллов на старте сессии: runtime-проверки — только в свежей сессии (`claude -p`)
- Некавыченный `: ` в YAML-описании молча выключал главного агента `finapp-mobile-expert`; ловится только строгим парсером в `agents:check`
- `memory: project` в Claude добавляет Write/Edit любой роли; `sandbox_mode = "read-only"` роли Codex не действует при записываемом sandbox родителя — «только чтение» для проверяющих ролей в обоих клиентах держится инструкцией
- Проектные хуки Codex без сохранённого доверия пропускаются молча; отсутствие напоминания ≠ неисправный хук
- Codex не раскрывает пути файлов инструкций — загрузку `AGENTS.md` проверять по содержанию ответа
- Поведенческая приёмка нашла то, что пропустили статические проверки: ревью только в чате, гейты после сбоя, недоступный `rtk yarn`. Все три — правки правил, не кода
- Независимый аудит нашёл потери при ручном переносе (git-граница двух ролей, правила `ai-models.md`) — перенос тел нужно сверять с `HEAD` построчно
- `rtk yarn` на Windows не запускает `.cmd`-шимы; `rtk proxy yarn.cmd` работает — fallback обязателен в точке входа, иначе агент его не увидит
- Лимит использования Codex остановил приёмку — runtime-проверки второго клиента планировать отдельным окном времени
- Codex CLI `--ephemeral` может не поддержать форк с полным контекстом: `no rollout found for thread id`; приёмку независимых ролей выполнять с обычным сохранением сессии
- Снимки исходников в evidence сохранять как текст: `tsconfig.json` включает `**/*.ts`/`**/*.tsx`, в том числе под `plans/`
- Копия для `agents:check` должна сохранять все проверяемые пути; локальные секреты не переносить, локальные настройки для ссылочной проверки допустимы как пустой файл только в тестовой копии

## Расхождения с design.md

- Codex-клиент — расширение VS Code вместо desktop: решение пользователя; runtime — через встроенный CLI `codex exec`, интерактив — `codex-close-phase.md`
- Изоляция read-only ролей Codex — инструкцией, не sandbox: наследование sandbox родителя (проверено)
- Переходный режим `agents:check` выведен из употребления: `package.json` запускает строгий по умолчанию после Phase 08
- Hook-команда — `node -e` с поиском git-root внутри Node вместо формы под конкретную оболочку: одна строка работает в cmd, PowerShell и bash, оболочка раннера не важна
- Добавлен Windows fallback `rtk proxy yarn.cmd`/`npx.cmd` и запрет мутаций через `rtk proxy git` в обоих клиентах — в design его не было
- Контракт review-артефактов расширен: любое запрошенное ревью, не только делегированное, сохраняется в `plans/**`
- Правило остановки гейтов на первом сбое вынесено в `AGENTS.md`; «не выполнено» ≠ «пройдено»
- `codebase-researcher` — BALANCED, а не FAST: сохраняет фактическую модель Claude (`sonnet`)
- `paths`-frontmatter убран из `ai/rules/design/*`: гейтинг — только стабы `.claude/rules/`
- Проверка из пути с пробелом в Codex-runtime невозможна: sandbox не пишет в ненастроенные каталоги; покрыто локальным запуском hook-команды
- Временный fixture `fixture-np/` лежит в папке плана до ручной приёмки — отступление от «без постоянных фикстур», удаляется после неё
