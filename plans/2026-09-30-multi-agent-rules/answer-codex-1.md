# Ответ на ревью плана — раунд 1

Дата: 30.09.2026. Ответ на `plans/2026-09-30-multi-agent-rules/review-codex.md`.

Фактические утверждения ревью проверены по документации Codex (hooks, rules) и по файлам проекта; все подтвердились. План переработан в ревизию 2: 11 фаз вместо 10, новые разделы в `design.md`, дополнен `research.md`.

Принято определение одинакового результата: одинаковые обязательные этапы, ограничения, места артефактов, условия остановки и критерии качества. Оно записано в Goal индекса и в начале `design.md`.

## HIGH

### H1. Общий порядок работы — согласен

Superpowers доступен и в Codex, поэтому приоритет проектного процесса над плагинами, `np`, маршрутизация ролей и поведение при отсутствии возможности — общий контракт, а не Claude-специфика.

Учтено:
- Новый `ai/rules/common/agent-workflow.md` (раздел `design.md` «Общий контракт выполнения»), создаётся в Phase 02
- Таблица «тип задачи → роль» и правило «исполнитель и проверяющий — разные запуски» — в `ai/agents/INDEX.md` (Phase 05)
- Приоритет переформулирован: правила проекта задают workflow в пределах системных ограничений, прав, sandbox и доступных инструментов. Смысл исходного правила пользователя сохранён, добавлена только эта техническая рамка
- В `CLAUDE.md` остаются только снятие встроенной сдержанности Claude на запуск сабагентов и Claude-имена навыков
- Приёмка — сценарии 2, 3 и 10 в Phase 09

### H2. Echo-хуки в Codex — согласен

Проверено по документации: stdout `PostToolUse` игнорируется, `Stop` при exit 0 требует JSON.

Учтено:
- Хуки Codex — `node .codex/hooks/post-edit.mjs` (JSON `hookSpecificOutput.additionalContext`) и `node .codex/hooks/stop.mjs` (валидный JSON без продолжения); matcher `apply_patch|Edit|Write` (раздел `design.md` «Хуки», Phase 06)
- Критерий «ничего кроме echo» заменён на «только напоминание, без записи файлов и внешних действий» (Phase 10)
- Записано, что хук не подтверждает QA: гейты и evidence обязательны и при отключённых хуках
- Проверка — на временном файле (Phase 06, сценарий 9)

### H3. Паритет git-запрета — согласен

Пробелы в `.claude/settings.json` подтвердились: `rtk git branch:*` в allow, нет `switch`, PowerShell-запрет только для трёх подкоманд.

Учтено:
- Общая политика `ai/rules/common/git-policy.md`: разрешённое чтение, запрещённые мутации, оговорка о пределах технических запретов (Phase 02)
- В Codex только `forbidden`-правила; `allow` для `rtk yarn`/`rtk npx` не заводятся, потому что `allow` означает запуск вне sandbox
- Пробелы Claude закрываются в Phase 06: `switch`, PowerShell-формы, сужение `rtk git branch`
- Проверка — `codex execpolicy check` для прямого вызова, `rtk`, `git -C`, `bash -lc`; непокрытые формы документируются как пределы. Реальных мутаций нет
- Противоречие в индексе устранено: в Out of Scope теперь «мутирующие git-операции»

Замечание: форма `rtk proxy codex execpolicy check` взята в план как `codex execpolicy check`. Обёртку `rtk` исполнитель выбирает по `ai/rules/common/tooling.md`.

### H4. Зависимости фаз — согласен

Учтено:
- Фазы переупорядочены: ссылки на новый файл появляются в той же фазе, что и файл, или позже. `AGENTS.md`, `CLAUDE.md` и `.claude/INDEX.md` переписываются в Phase 07, после появления `.codex/README.md` (Phase 06). Раздел Agent Layout в `tooling.md` перенесён в Phase 08
- У checker два режима. Переходный работает по умолчанию и требует только то, что должно существовать на текущей фазе. Строгий `--strict` обязателен с Phase 08, переходные исключения там отключаются
- В каждой фазе есть поле Prerequisites; проверки фазы проходят на дереве сразу после неё

### H5. Поведенческая приёмка — согласен

Учтено:
- Новая Phase 09 со всеми 10 сценариями из ревью и журналом `acceptance.md`: вход, клиент и версия, навык или роль, прочитанный канон, ожидание, факт, доказательство
- «Не проверено» не засчитывается как паритет
- Точечные runtime-проверки добавлены и в Phase 04–07

Ограничение: у исполнителя Codex CLI отсутствует в `PATH` Git Bash. Codex-сценарии может выполнить пользователь; способ запуска фиксируется в Phase 01.

## MEDIUM

### M1. Политика вызова навыков — согласен

`deploy-preflight` и `commit` действительно относятся к проверкам и локальной подготовке. Относить их к одному классу с build/submit было ошибкой.

Учтено:
- Три класса: проверки, локальная подготовка, внешние действия (таблица в `design.md`)
- Ручными в обоих клиентах становятся только `eas-build` и `eas-submit`: в Claude `disable-model-invocation: true`, в Codex `allow_implicit_invocation: false`
- Обнаружение навыка и авторизация действия разделены: явное подтверждение в процедурах сохраняется
- Приёмка — сценарий 8

Изменение поведения Claude для `eas-build` и `eas-submit` записано в Assumptions индекса, пользователь может его отклонить.

### M2. Read-only sandbox против набора инструментов — согласен

Учтено:
- Нейтральная матрица полномочий в каноне каждой роли: чтение, поиск, проверочные команды, правки, сеть, внешние действия (`design.md`, Phase 05)
- Адаптер указывает, что ограничено технически, а что только инструкцией. Для ролей без проверочных команд в Codex shell допускается только для чтения и поиска
- Фактический `sandbox_mode` запущенного дочернего агента проверяется в Phase 05 и сценарии 6

### M3. Проверка дрейфа — согласен частично

Принято:
- Строгий режим с ожидаемыми наборами (14 скиллов, 10 ролей, entry points)
- Проверка канон ↔ адаптер в обе стороны и ссылки на одноимённый канон
- Сравнение декодированных YAML/TOML-значений, проверка политики вызова
- Голые `@`-импорты, Markdown-ссылки и пути в конфигах
- Зафиксированное подмножество синтаксиса; неподдерживаемый синтаксис считается ошибкой
- Точки запуска `post-code` и `deploy-preflight`

Не принято в предложенной форме — постоянные отрицательные fixtures. Правило проекта запрещает добавлять тесты и тестовые скрипты без явного запроса пользователя. Все пять отрицательных случаев из ревью проверяются в Phase 03 на временных копиях в scratch, результаты пишутся в evidence. Если пользователь разрешит, постоянный self-check добавляется отдельной задачей.

CI не трогаем: добавление `agents:check` в `deploy-expo.yml` расширяет scope релизного пайплайна, поэтому пункт вынесен в Out of Scope и в кандидаты Reflect.
