# Переключатель режимов отображения расходов — Implementation Plan

Дата: 14.09.2026

## Goal

- Экран статистики получает сегмент-контрол на два режима: иерархия категорий и плоский список подкатегорий
- Плоский список показывает подкатегории и категории без подкатегорий, отсортированные по доле затрат, с полной сходимостью суммы с «Потрачено»

## Task Profile

`feature` — 3 feature-сигнала против 0 bugfix-сигналов.

Feature-сигналы:
1. Новая UI-поверхность экрана — сегмент-контрол и второй тип карточки списка
2. Новая производная модель данных — плоская строка, синтетический остаток, составные ключи списка
3. Архитектурный трейд-офф — место хранения режима и место вычисления плоского списка, разбиение хука, вышедшего за лимит

Bugfix-сигналы: детерминированного репро нет, корректирующих изменений контракта нет.

## Decisions Taken

- Целевая версия — `1.10.0`
- Расходы категории, не отнесённые ни к одной подкатегории, в плоском режиме показываются синтетической строкой «Без подкатегории» с суммой остатка и без бюджета

## Assumptions

- Режим отображения живёт в локальном состоянии экрана, без персиста между сессиями и без Zustand — `src/shared/stores/` не создаётся
- Режим по умолчанию — «Категории»
- Сортировка плоского списка по `totalSpent` убыв. эквивалентна сортировке по проценту затрат: знаменатель общий
- Бэкенд-контракт не меняется, `rtk yarn api:generate` не запускается
- Изменения только в JS — доставка OTA-совместима, `expo.runtimeVersion` остаётся `2.0.0`
- Порог предупреждения бюджета остаётся тем, что задан в `getProgressColor`, единым для обоих режимов
